# 可以逐阶段复制给执行 agent 的指令

每次只发当前阶段。输入文件不足时先列出具体缺项，不能用近似版本补齐。以下指令不授权主榜变更或发布。

## P0：先把运行条件固定

> 阅读 benchmark/selection/hard_next_plan_20260912/README.md 与 SERVER_RUNBOOK.md，执行 P0。为新研究建立独立配置和来源/参考计量绑定；核实模型别名、镜像、Python、120 steps、3600 秒和上下文上限，保留生效配置及 hash。用旧三题最多做 3 次 canary，不开展新题模型实验。不得修改主榜、旧三题题包或已有结果。交付 environment.json、canary 结果、输入与来源审计、明确的继续/停止结论。密钥只从本地忽略的 env 文件读取，不进入日志、包或报告。

## P1：六例规格与失败审查

> 按本方案 P1，完成 tenacity、glom、alembic、requests-cache、pluggy、responses 六张案例卡。使用对应历史 run 的 TASK、测试、来源、提交和错误日志逐项核对，不混用 freeze。区分真实适配、语义组合遗漏、规格风险、基础设施问题与未确定；列明实际消费者理由和最小可能修复。请独立 reviewer 复查，明确其类型。暂不修改冻结任务、制作新题或运行 API。交付六张 case_card、证据路径与 hash、规格风险清单和 P2 可构造性判定。

## P2a：创建对照版本并验证

> 在 P1 通过的基础上，按 experiment_matrix.json 创建研究版本 O/C/N。只物化具备来源与契约证据的版本。O 保持原版功能输入，C 明确消费者协议，N 仅用于 tenacity/glom 的原生协议诊断；范围变化必须显式记录。新 task ID 放在 staging，原题和主榜不变。交付版本差异、公开规格、逐断言映射、独立参考、三个 Docker oracle 重复、完整 source/reference 绑定、输入锁和评审结论。先不运行模型，也不暴露源入口提示。无法恢复原版就标缺失，不编造。

## P2b：运行封存后的对照

> 环境与 O/C/N 输入锁均通过后，用已封存的 Flash/OpenHands 条件执行 P2 首轮，最多 14 次独立运行，最大并发 2，不自动重跑失败。只在主方案规定的 C/N 有价值差异上追加确认，新增最多 8 次，并先记录追加依据。不得改题或择优汇总。交付每次 run/result/submission/usage、协议有效性审查、O/C/N 判读表和是否进入 P3 的结论；不能声称小样本证明 25%–45%。

## P3：寻找并构造全新切片

> 只有 P2 支持继续时才执行。围绕已验证且有实际用途的适配机制，查找最多 6 个真实上游来源；审查 pinned commit/license/行为测试与现有题重叠。最多物化 3 个不同闭包的新候选，不能把原三题或同一 wrapper 改名充数。每题先有真实 consumer example，再写契约。上游继承部分做差分，适配部分做独立契约 oracle，交付三类实做基线、Docker 隔离证据和封存输入。整包改名加薄适配能通过则退出本轮功能 hard 池，不改判其功能成绩。先不启动模型；交付完整题包和可校准性结论。

## P4：新原型筛查

> 对通过 P3 审查的最多 3 题，在固定版本和预算下各跑 Flash 2 次，最多 6 次；有效版本再各跑第二模型 1 次，最多 3 次。所有运行独立、保留全部失败，禁止试后增改 hidden。按方案区分偏易、潜在困难、规格无效和环境不可判，给出逐题去留理由。提交结果后停止，不自动扩到 12/50，也不声称目标带已达到。
