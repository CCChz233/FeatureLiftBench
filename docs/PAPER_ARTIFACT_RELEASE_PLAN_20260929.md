# FeatureLiftBench 论文复现材料发布计划（供审阅）

状态：计划草案，2026-09-29。本文只确定工作范围和验收标准；尚未装配、验证或上传发布包。以当前论文的 **150 个 Python 任务**为范围。如果投稿前论文改用新的任务集或 RQ2 数据，应先更新冻结清单，再执行本计划。

## 1. 目标与发布边界

交付一个审稿人可以下载、检查和运行的版本，使其能够：

1. 查看 150 个任务的公开契约、上游身份、固定版本、entrypoint 声明和依赖要求；
2. 恢复固定版本的上游源码，并核对源码树哈希；
3. 在隔离的 agent 工作区外运行同一评测器和测试；
4. 从逐题结果重算论文表格、统计量和图；
5. 检查 DSE 的冻结映射、生成规则和 40 题结果；
6. 了解原始轨迹、提交产物及用量记录实际保存了多少，哪些缺失。

发布分两部分：**小型代码仓库**放任务定义、代码、配置和论文逐题数据；**数据附件**放经审查的大型原始记录和可发布的产物。二者用版本号、文件清单和 SHA-256 绑定。当前工作仓库及其历史不直接作为匿名发布包。

## 2. 建议交付结构

以下是导出包的结构，不要求重构现有开发仓库。首次导出尽量保留 Python 模块的原有相对路径，以免破坏导入和结果来源。

```text
featureliftbench-artifact/
├── README.md                     # 三种复现层级、环境、命令、数据覆盖率
├── LICENSE                       # 我们有权许可的代码和任务材料的范围
├── CITATION.cff
├── MANIFEST.sha256
├── benchmark/
│   ├── tasks/<150 task IDs>/     # TASK.md、metadata.json、lock、测试、评测配置
│   └── sources/registry.json     # 126 仓库、132 快照的身份及哈希
├── harness/                      # 实际 agent/评测调用链
├── docker/                       # 可构建的 agent/evaluator 镜像定义
├── scripts/                      # 源码恢复、运行、校验的真实入口
├── experiments/dse/             # DSE 规则、40 题冻结映射与结果；不含源码副本
├── docs/paper-workbench/         # 论文输入清单、分析与绘图代码、消融逐题结果
├── reports/paper_analysis/       # 900 主实验等冻结逐题结果及说明
└── provenance/                  # 论文范围、配置、例外、原始证据覆盖率
```

`contract.yaml` 不是必需的新文件。当前规范契约在 `metadata.json` 的 `public_spec` 中，agent 看到的 `TASK.md` 由它生成。导出时保留二者，验证内容一致，不再维护第三份手写契约。公开元数据可以包含 entrypoint；运行器仍必须生成**不含 entrypoint 和评测信息**的 agent 可见元数据。测试可以公开供复现，但运行时不能挂载给 agent。

## 3. 复用现有材料，而不是重写

| 交付项 | 现有来源 | 还需完成 |
| --- | --- | --- |

| 上游身份 | `benchmark/sources/registry.json` | 导出当前 150 题对应的 132 个快照；保留 URL、resolved commit、获取方式、源码树哈希、归属和许可信息 |

| RQ2 结果 | `docs/paper-workbench/data/source_ablation_retained_20260921/` | 检查 240 条保留结果、40 题 DSE 与论文数值一致；注明旧版/被替代结果 |

现有源码 registry 记录 **126 个仓库、132 个快照**，其中 **131 个 `git_checkout`、1 个 `official_vcs_archive`**。因此“URL + commit + 简单 clone 脚本”覆盖不了全部冻结材料。源码恢复还必须验证 `source_tree_sha256`，不能只验证 checkout 成功。

## 4. 工作步骤和每步验收

### A. 冻结论文口径

- 将 150 题 membership、论文输入清单、主实验 900 条、消融 240 条、DSE 40 条和当前图表绑定到一个版本清单。
- 记录每个统计结果的输入路径、文件哈希、筛选规则和运行配置。保留历史例外，不用新运行替换旧运行。
- **验收**：清单中的任务数与结果格子数正确；论文中的每个主要数值都有逐题输入和重算命令。

### B. 白名单装配任务与源码恢复能力

- 从 150 个任务目录复制定义、锁文件、评测配置和测试；不复制 `repo/`。导出 registry 和现有物化脚本所需的最小依赖。
- 对 task statement 与 `public_spec` 做一致性检查；对 agent 工作区做脱敏检查，确保公开的 entrypoint 不会在 Main/Contract Only 运行时成为 agent 提示。
- 在独立目录恢复 132 个快照，核对 commit、源码树哈希；记录无法再从上游取得的快照，并决定是否能提供经许可审查的替代来源。
- **验收**：150 题定义齐全；132 个快照可恢复且哈希匹配，或有逐项列明的未解决例外。不能把“仓库可 clone”当作通过。

### C. 装配可运行评测和 DSE

- 保留实际用到的 harness、Dockerfile、配置与依赖；导出论文所用的模型/agent 配置，区分历史运行配置与当前重跑配置。
- 核查 Docker 构建输入是否都在发布包或可按固定版本下载。当前 `docker/Dockerfile.agent` 引用了本地不存在的 `benchmark/vendor-wheels`，发布前必须修复这条构建链并验证，而不是只复制 Dockerfile。
- DSE 导出 v1.2 冻结规则、40 题选择及别名映射；用公开契约和恢复的上游源码重新生成、评测，比较逐题结果。
- **验收**：全新副本能构建镜像；至少完成每类任务的端到端 smoke，并对 150 个 reference/oracle 任务完成重评或列出明确例外；DSE 40 题的规则、输入哈希和结果可核对。

### D. 装配论文数据和分析

- 在代码仓库放逐题 CSV/JSON、统计代码、图表代码、任务选择和字段说明。首版保留现有相对路径；保留分母、缺失值、重试/保留规则及随机种子。
- 为原始运行数据分别统计 `run.json`、轨迹、submission、usage、评测结果的可用数量，生成机器可读的覆盖率清单。已有发布盘点曾报告主实验 profile 仅 307/900；装配时必须重新核查当前状态。
- 大型轨迹与产物只发布已恢复且完成敏感信息、来源/许可审查的部分；不能声称有完整 900 次原始运行包。含上游复制代码的 submission 也按第三方材料处理。
- **验收**：从发布目录的冻结逐题结果重算论文主要表格和图，数值与投稿版本一致；任何无法复算或缺少原始证据的项目在 README 中逐项说明。

### E. 发布审计

- 为自有代码和任务材料明确 LICENSE；生成第三方来源与许可清单。默认不分发 126 个完整上游仓库、不分发源码归档，也不分发未经审查的 DSE/agent 源码副本。
- 扫描导出文件与**新仓库的完整 Git 历史**中的密钥、认证头、个人路径、作者标识、失效绝对路径、符号链接和意外的大文件。当前开发仓库已有个人 Git remote 和大量历史文件，匿名包必须从筛选文件建立全新历史。
- 从干净副本执行安装、源码恢复、Docker smoke、评测和数值重算；生成包含文件哈希与验证记录的发布报告。
- **验收**：公开包不含 `.env`、真实私密配置、上游源码快照或未经审查的产物；所有文档命令在干净副本执行成功；失败与例外可见。

### F. 分两阶段发布

1. **投稿阶段**：按目标会议的匿名规则创建全新仓库和数据附件。上传前检查仓库 owner、提交作者、文件内容、外链及数据附件的 creator 元数据。把匿名链接写入论文前，先验证审稿人无需个人账号即可访问。
2. **录用后**：核对最终版本，建立正式 GitHub release 和持久数据记录，记录 DOI、版本、SHA-256 与两者的对应关系。Zenodo 的常规公开记录需要 creator 元数据，发布后不能替换原记录中的文件；不默认把它当作匿名投稿存储。

此阶段的验收是链接可访问、下载文件哈希正确、README 命令仍能执行。**本计划不授权现在上传、公开或创建远程仓库。**

## 5. 复现声明分三个层级

README 和论文的数据可用性表述必须分清：

1. **数值复算**：用发布的逐题结果重算论文表格、统计量和图。首版必须做到。
2. **独立重评**：恢复上游源码，对已保存的 reference/DSE/agent 产物重新运行评测。以实际可发布产物和验证覆盖率为准。
3. **重新运行模型实验**：读者自备对应模型访问与计算资源，按冻结配置重新运行；结果不保证逐次一致。首版提供配置和命令，不要求重新生成历史 900 个结果。

## 6. 需要审阅的决策

- 公开测试采用“与代码同仓库”还是“独立版本化数据附件”；两种方案都必须保证 agent 运行时看不到测试。
- 参考实现及含上游复制代码的 agent/DSE 产物，经许可审查后能公开到什么程度；不能公开时，复现声明相应收窄。
- 投稿目标会议的匿名 artifact 规则和允许的托管平台。现有个人 Git remote 不能直接充当匿名投稿地址。
- 自有代码和任务材料分别采用什么许可证；不要把论文模板的 LPPL 误作整个项目许可证。

计划通过后才开始装配。实施过程中先产出本地候选包和验收报告，最后再确定远程发布地址与论文中的 Data Availability 链接。
