# 当前结果能说明什么

> **Status: archived · Last verified: 2026-08-04**
> 本文是合并前快照；当前解释边界见 [STATUS.md](../../STATUS.md)。
> 具体数字只在 [STATUS.md](../../STATUS.md) 维护，本文件只维护解释边界。

## Supported

- FeatureLift tasks discriminate strongly between evaluated coding agents under the audited
  baseline condition.
- Agent completion status is not a reliable replacement for evaluator Functional Pass;
  functionally valid submissions can be produced by runs that later hit step or time limits.
- The complete baseline models can be compared on the same frozen task set after evaluator
  environment resolution.
- Task-level logs, submissions and usage records support failure attribution and cost/process
  analysis even when the suite-level generated summary is stale.
- The balanced extension is package-complete and runnable, so it can extend compatible
  baseline suites without rerunning successful or failed baseline attempts.

## Not Yet Supported

- A final Python-200 leaderboard: External model runs are not complete.
- A full DeepSeek Python-200 score from the archived evidence: its baseline is incomplete.
- Exact claims tied to the declared frozen evaluator environment until image mismatch is
  attested or submissions are re-evaluated.
- Context-independent ranking for models with context-window violations without sensitivity
  analysis.
- Headline plagiarism/copying claims from `copied_fraction`; closure-gold completeness still
  requires review.
- Generalization beyond the selected Python repositories, task construction process and
  tested agent condition.

## Paper Analysis Priorities

1. Complete compatible External extension runs and normalize evaluator environment.
2. Report Functional Pass@1 with Wilson intervals and task-paired comparisons.
3. Stratify by lift type, entanglement/family and task difficulty only after checking cell size.
4. Separate capability failures from context, infra and process failures.
5. Treat historical method pilots as mechanism evidence or negative results, not Main scores.
