- 任务边界明确：完整 donor repository 可见，产物在无 donor 的环境中运行；允许抽取、适配或重写，按公开行为契约验收。

- RQ3 已区分保留上游行为和 destination adaptation；三组成功/失败案例比笼统的 behavior drift 标签更能承载 SE 启示。

## 按优先级列出的主要问题

### P0：投稿页数超限

证据：当前 PDF 正文到第 20 页，参考文献起始第 21 页。历史进度文档写过 23/24 页和参考文献起始第 22 页，应以当前 PDF 为准。

处理：优先缩减 RQ2/RQ5、footprint 统计实现细节及重复的边界说明，合并重复图表。不要缩小模板字号或修改边距。压缩后重新编译核对，而不是按删掉的源码行数估计页数。

### P1：13 条评测疑点只从解释样本排除，主结果影响未交代

位置：`main.tex:287` benchmark validation；`main.tex:914` analysis-set flow。

正文一面宣称 150 题经过语义验证，一面从 241 条源码暴露失败中排除 13 条 contract/evaluator mismatch candidates。读者无法判断这些候选最终被驳回、确认还是仍未决，也无法判断其涉及的任务是否仍在 RQ1 和 source ablation 中作为失败计分。

当前 `data/failure_analysis_20260916/provenance.json` 明确保留该排除口径。历史 `writing/known_defect_sensitivity.json` 和 `defect_reconciliation_20260909.json` 另有疑点及敏感性记录，但不能自动把旧 7-task 集合等同当前 13-run 集合，也不能用旧助手判断推翻后来的作者复核。

最低修复：形成当前 13 run → task → 裁决 → 主实验/消融影响的可追溯说明。若疑点驳回，补充具体条款和裁决理由；若确认影响有效性，对所有配置采用一致的任务级处理或版本化重评，并报告敏感性。不能只删掉发生争议的失败 run，也不能直接把其记作通过。

这是最可能从一个局部遗漏升级为整篇 benchmark soundness 质疑的问题。

### P1：标注方法的概述不足以解释最终 176 条结果的可靠性

位置：`main.tex:587`。

40-case 双人 pilot 和后续 contract-question review 已在正文说明，但剩余 161 条的标注职责、适用规则、复核覆盖，以及一致性统计都没有交代清楚。现有台账已经承认后续 90 条由作者确认复核通过；本审阅不把它们当作尚未复核。

不过，`reports/paper_analysis/se_obligations_pilot_20260918/review_summary.md` §6.1 保存了有解释价值的原始分歧：开发集义务状态一致 16/30；双方都确认且属性适用的 13 条中，主属性一致 9/13。冻结规则后的 A/B 10 条一致，C 的额外对照又揭示分歧。不同阶段/版本和条件分母不能混合，后续共识不能替代讨论前一致性。

最低修复：正文短述“谁、在哪个阶段、标注哪些维度、复核多少、如何裁决”；补充材料给阶段化一致性、主要混淆和代表性规则修订。将已有 90 条复核结论链接到对应条款/理由，不必为论文外观机械地新增一轮全量双人标注。是否增加验证，应由现有证据是否足以支撑结论决定。

### P1：现实复用需求及独立 benchmark 的必要性仍偏抽象

位置：`main.tex:67`、`:239`、`:342`、`:1268`。

“开发者可能需要 parser/configuration/signal registry”合理，但不是需求证据。56 Direct、76 Adapted、18 Composite 中，近三分之二涉及适配或组合；这些目标接口为何值得这样设计、是否来自真实复用需求，正文缺少具体来源。

Related Work 已承认 FeatureBench 包含从零构建，因此不应把“独立 package”单独作为新颖性依据。更强的定位是：完整既有实现作为证据、契约明确规定目标边界、源隔离执行、并观察行为在该转换中如何失配。

最低修复：给 2–3 个可核验真实复用场景，说明其与任务设计的对应关系；若任务由作者构造，明确是 source-grounded constructed tasks，不暗示它们都是自然发生的迁移请求。补充候选来源、筛选/排除原则、构造时 AI 的实际参与和任务范围冻结时序。

可以评估一个统一规则的简单复制/依赖闭包打包基线，特别是 Direct 子集，以回答“为何不能复制源码后包一层接口”。这是高价值补强选项，不是所有 benchmark 论文都必须具备的门槛；不能预设该基线必然失败。

### P1：SE insight 仍停留在通用属性列表，跨边界转换的解释需要更具体

位置：`main.tex:966`、`:1019`、`:1162`。

value/call/validation 合计 69.3% 是选定确认样本的构成，当前限定语是正确的。但这些属性在一般代码生成失败中也很常见，仅报比例尚不能说明 feature lifting 的特有困难。三组案例承担了大部分 supporting relationships 的证据，且只有部分是“原有关系丢失”，其他是新适配义务。

最低修复：把一例展开为可检查的短代码/行为对照：原假设 → 目标契约改变 → 失败实现的不一致 → 成功实现如何满足义务。跨案例综合为有限的、可迁移的验证建议，并明确哪些是 preserved upstream、哪些是 adaptation-induced。无需将所有 176 条强行解释为关系丢失，也无需为了证明“最难”再建立全量属性机会分母。

### P2：五个 RQ 的叙事优先级与核心问题不一致

位置：`main.tex:630`。

引言提出跨包边界的行为保留，结果却在 RQ1 后先讨论执行停止，随后才讨论失败与源码证据。RQ5 又引入较长固定效应/聚类 bootstrap 描述。各分析单独有意义，但当前安排容易读成多个离线统计的集合。

建议主顺序：总体可行性与结构差异 → 仓库证据的作用 → 哪些行为义务未保留及案例。RQ2 和 RQ5 可作为 secondary analyses 缩写，详细估计方法放补充材料。若保留五个编号，也建议调整顺序、篇幅和贡献段，而非平铺同等重要的五项。

Table 1 的 RRES/Copy 均值、中位数、四分位数，加上 Steps/Tokens，使主发现拥挤；token 又有不同计费口径。优先保留 correctness 和必要描述，其余放补充表。Source ablation 的图和完整表存在压缩空间，但至少保留 discordant pairs、CI 和配对检验信息。

### P2：实验设置仍存在可复现性与术语缺口

位置：`main.tex:420`、`:431`、`:712`、`:532`。

- 最大 120 interaction steps 与 Table 1 中 GLM 的 Steps P90=127.0 看似矛盾。生成器读取的是 `process_assistant_steps`。这可能是不同计数器，而非真的违反预算；应在正文/表注定义二者对应关系，不能直接下结论说实验超预算。
- 缺少运行日期、确切模型标识/版本、采样和 reasoning 设置、关键执行参数的紧凑索引。模型显示名与 OpenHands 版本不足以独立复现。
- “one retained outcome”需要解释主实验的尝试选择规则；消融中只有 Pro Contract Only 的 18 个无提交运行得到额外尝试，现有披露值得保留，但应提供原始尝试结果和统一策略敏感性，避免被理解为两臂严格相同执行机会。
- 历史材料记录过不同 freeze/image identities 的对账问题。仅凭旧记录不能判定当前实验失效；匿名材料应把每个正式 run 与 task/contract/evaluator 身份以及现有对账结论连接起来。
