> DeepSeek Python-200
> 互斥首败优先级：未交付 → Build → Public → Hidden → Isolation

## 当前可确认的分布

| 端点 / 方法 | Functional Pass | 未交付 | Build | Public | Hidden | Isolation | 阶段证据缺失 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| API Main | 144 | 5 | 1 | 24 | 21 | 0 | 5 |
| API Lite V1 | 131 | 8 | — | — | — | — | 61 |
| 本地 Main | 145 | 2 | — | — | — | — | 53 |
| 本地 Lite V1 | 127 | 2 | 2 | 39 | 30 | 0 | 0 |

“阶段证据缺失”不是新的失败原因，而是本地结果包没有保留足够的逐题
evaluator 产物。不能将它们猜成 Public 或 Hidden。

## 能说的结论

本地 Lite V1 有完整的 Python-200 阶段证据。它的 73 个 Functional Fail 中：

- Public 首败 39 题（53.4%）；
- Hidden 首败 30 题（41.1%）；
- Build 2 题（2.7%）；
- 未交付 2 题（2.7%）；
- Isolation 首败 0 题。

所以 Lite V1 的主要问题是两层契约未闭合：Public 已经暴露了较多主路径错误，
过了 Public 的解又在 Hidden 边界、状态和完整 API 上失败。

## 尚不能说的结论

在 API Lite 和本地 Main 的逐题 `eval/result.json` 补齐前，不能严格比较“Lite 比
Main 多了哪类失败”。API Main 的已知 Build/Public/Hidden 只覆盖 Main-150，
External-50 的 5 个失败尚缺阶段证据。
