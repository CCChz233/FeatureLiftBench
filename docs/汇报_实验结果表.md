# DeepSeek Python-200 方法对比

> **Status: current · Last verified: 2026-08-17**
> 用途：组会 / 汇报直接投屏；方法：Main vs Frozen Lite V1；
> 核心指标：Functional Pass Rate + RRES。
> 日期：2026-08-17

## 主结果

| 运行端点 | Main Functional Pass | Lite V1 Functional Pass | Lite 差值 | 可比的 paired RRES |
| --- | ---: | ---: | ---: | --- |
| API | **144/200 (72.0%)** | 131/200 (65.5%) | **-13 题 / -6.5 pp** | N/A：Lite 逐题 eval 缺失 |
| 本地 vLLM | **145/200 (72.5%)** | 127/200 (63.5%) | **-18 题 / -9.0 pp** | N/A：Main 逐题 eval 缺失 |

**一句话：Frozen Lite V1 更省资源，但在两个端点都明显损失 Functional Pass，尚不能取代 Main。**

## 成对结果

| 范围 | 两者都过 | 仅 Main 过 | 仅 Lite 过 | 两者都失败 |
| --- | ---: | ---: | ---: | ---: |
| API Main-150 | 84 | **15** | 4 | 47 |
| 本地 Python-200 | 125 | **20** | 2 | 53 |

Lite 丢掉的 Main-pass 题远多于它救回的 Main-fail 题，方向在 API 和本地运行中一致。

## 汇报时必须说清

- `final_score == functional_gate`；Average Final Score 不代表紧凑度。
- 历史 `summary.passed` 是运行状态，不是 Functional Pass。
- RRES 只在 Functional Pass 题上计算，两方法比较需使用同题双通过子集。
- Tokens、steps 和时间是成本诊断，不是核心质量指标。
